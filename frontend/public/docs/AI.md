# Сводка по взаимодействию через GigaChat (ФТ-6)

ТЗ допускает применение ИИ к данным о вузах. В RTK CRM это одна функция:
сводка по карточке взаимодействия. КАМ открывает карточку и получает
короткий текст — на каком этапе вуз, что уже сделано, что требует внимания
и какой следующий шаг. Цель практическая: восстановить контекст перед
звонком, не перечитывая всю переписку.

## Что попадает в сводку

| Поле | Источник |
| --- | --- |
| Вуз | `University.name` |
| Продукт | `ITProduct.name` |
| Этап | `WorkflowStageRef.name` |
| Скоуп | `Interaction.scope` (B2B или B2C) |
| Ответственный КАМ | `User.full_name` |
| Задачи | `Action.title`, `is_completed`, `due_date` |
| Комментарии | `Comment.text` |

Персональные данные в промпт не уходят. СНИЛС, паспортные данные, адреса и
телефоны в карточке не хранятся — они отбрасываются ещё на этапе импорта
(см. `docs/SECURITY.md`). В промпт передаются только названия, тексты
комментариев и служебные поля.

## Как это работает

Запрос идёт в два шага, как требует GigaChat:

1. Ключ авторизации (`GIGACHAT_CREDENTIALS`) отправляется в OAuth
   (`/api/v2/oauth`) в заголовке `Authorization: Basic`. В ответ приходит
   токен доступа на 30 минут. Заголовок `RqUID` обязателен — без него
   сервис отвечает 400.
2. Запрос к модели (`/chat/completions`) идёт с `Authorization: Bearer`.

Токен кэшируется в памяти процесса и обновляется заранее, за минуты до
истечения срока. Один токен обслуживает все запросы, поэтому OAuth не
вызывается на каждую сводку.

Ответ модели ограничен 150 словами и температурой 0.3: нужна сводка фактов
из карточки, а не творческий текст. Системная инструкция прямо запрещает
добавлять сведения, которых в данных нет.

## Настройка

Минимально достаточно одного ключа:

```env
GIGACHAT_CREDENTIALS=<authorization-key-base64>
```

### Сертификат НУЦ Минцифры

GigaChat предъявляет сертификат, выпущенный НУЦ Минцифры. Его корня нет
в стандартном наборе доверенных сертификатов Python и большинства
Linux-образов, поэтому без него TLS-соединение падает с
`CERTIFICATE_VERIFY_FAILED`, и сводка не работает ни при каком ключе.

Сертификат поставляется в репозитории (`backend/certs/russian_trusted_root_ca.pem`),
вшивается в образ (`backend/Dockerfile` кладёт его и в системный набор, и в
`/certs`) и монтируется в контейнер из `docker-compose.yml`. Отдельно
настраивать ничего не нужно: код сам берёт файл из `/certs`, а при локальном
запуске — из `backend/certs/`. Переменная `GIGACHAT_CA_BUNDLE` нужна только
если сертификат лежит в нестандартном месте.

Отключение проверки TLS (`GIGACHAT_VERIFY_SSL=false`) — крайняя мера для
отладки: в рабочем контуре проверка включена.

## Поведение без ключа и при сбоях

Функция спроектирована как необязательная: её отказ не должен ломать
основной сценарий работы с карточкой. В демонстрационном контуре
(`GIGACHAT_FALLBACK_ENABLED=true`) отказ внешнего сервиса не показывается
пользователю как ошибка: вместо этого сводка собирается из данных карточки.

| Ситуация | Ответ при `FALLBACK=false` | Ответ при `FALLBACK=true` |
| --- | --- | --- |
| `GIGACHAT_CREDENTIALS` не задан | 503 | 200, демо-сводка |
| OAuth отклонил ключ | 502 | 200, демо-сводка |
| GigaChat недоступен или 5xx | 502 | 200, демо-сводка |
| Неожиданный формат ответа | 502 | 200, демо-сводка |
| Нет доступа к карточке | 403 | 403 |

Демо-сводка — это детерминированный текст, собранный из полей карточки
(`gigachat.build_fallback_summary`): вуз, продукт, этап, ответственный,
счётчик задач и последний комментарий. Он не содержит сгенерированных
утверждений, и в поле «Модель» такого ответа стоит
`демо-сводка (GigaChat не вызывался)` — то есть демо-текст нельзя принять
за ответ модели.

Ошибка внешнего сервиса не превращается в 500: по коду ответа видно, что
проблема на стороне GigaChat, а не в CRM. Данные чужой карточки при этом
во внешний сервис не уходят — доступ проверяется до сборки промпта.

## Код

- `backend/services/gigachat.py` — авторизация, кэш токена, сборка промпта,
  разбор ответа, типы ошибок `GigaChatDisabled` и `GigaChatUnavailable`,
  демо-сводка `build_fallback_summary`. Модуль не вызывается из `/readyz`:
  недоступность необязательной функции не должна переводить сервис в degraded.
- `backend/api/interactions.py` — эндпоинт
  `POST /api/interactions/{id}/summary`.
- `frontend/src/components/interaction/InteractionDrawer.tsx` — вкладка
  «Сводка» с кнопкой и временем генерации.

## Тесты

`tests/test_gigachat_summary.py` — 16 тестов. Внешний сервис подменяется
транспортом httpx: GigaChat платный и недоступен в CI, а проверяется наш
код, а не чужой сервис. Покрыты сборка промпта, оба шага авторизации, кэш
токена, коды 503 и 502, запрет доступа к чужой карточке и оба режима
демо-сводки — по отсутствию ключа и по сбою внешнего сервиса.
