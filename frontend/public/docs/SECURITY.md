# Безопасность RTK CRM

## Обзор безопасности

RTK CRM разработан с учётом требований 152-ФЗ и стандартов информационной безопасности.

## Защита данных

### Шифрование

- Все пароли хешируются с использованием bcrypt
- Передача данных по HTTPS
- Защита от SQL-инъекций через ORM

### Аутентификация

- JWT-токены для сессий
- Время жизни токена: 24 часа
- Автоматическое истечение сессии

### Авторизация

- Ролевая модель доступа (RBAC)
- Три роли: user, manager, admin
- Проверка прав на каждом эндпоинте

## Аудит действий

### Запись событий

Все действия пользователей записываются в журнал аудита:
- Создание, редактирование, удаление данных
- Вход и выход из системы
- Экспорт данных
- Загрузка файлов

### Хранение логов

- Логи хранятся в базе данных
- Фиксируется: пользователь, действие, timestamp, IP-адрес
- Соответствие 152-ФЗ

## Безопасность паролей

### Требования к паролям

- Минимум 6 символов
- Рекомендуется: 8+ символов
- Хеширование bcrypt

### Сброс пароля

- Сброс пароля выполняется администратором
- После сброса пользователь должен сменить пароль

## Защита от атак

### CORS

- Настроен список разрешённых origins
- Запрещены wildcard-запросы с credentials

### Rate Limiting

- Рекомендуется настроить rate limiting на уровне сервера
- Защита от brute-force атак

### Валидация входных данных

- Все входные данные валидируются
- Защита от XSS и CSRF

## Резервное копирование

### Автоматические бэкапы

- Ежедневные бэкапы базы данных
- Хранение в защищённом хранилище
- Периодичность: 24 часа

### Восстановление

- Время восстановления: не более 4 часов
- Процедура восстановления документирована

## Соответствие стандартам

### 152-ФЗ

- Аудит действий пользователей
- Защита персональных данных
- Хранение логов не менее 6 месяцев

### GDPR

- Право на удаление данных
- Право на экспорт данных
- Обработка согласия на обработку

## Рекомендации

### Для администраторов

- Регулярно обновляйте пароли
- Деактивируйте учётные записи уволенных сотрудников
- Проверяйте журнал аудита
- Следите за обновлениями системы

### Для пользователей

- Не передавайте свои учётные данные третьим лицам
- Используйте сложные пароли
- Выходите из системы после завершения работы
- Сообщайте о подозрительной активности

## Инциденты безопасности

### Сообщение об инцидентах

При обнаружении инцидента безопасности:
1. Немедленно сообщите администратору
2. Не пытайтесь самостоятельно устранить проблему
3. Сохраните логи и доказательства

### Процедура реагирования

1. Оценка серьёзности инцидента
2. Ограничение доступа
3. Расследование
4. Устранение уязвимости
5. Отчёт о мерах

## Соответствие 152-ФЗ и приказу ФСТЭК № 117

### Обрабатываемые персональные данные

| Категория | Состав | Основание |
|---|---|---|
| Сотрудники Ростелекома (пользователи) | ФИО, e-mail, роль, хеш пароля | трудовые отношения, ст. 6 ч. 1 п. 5 152-ФЗ |
| Контакты вузов | ФИО, должность, рабочий e-mail, рабочий телефон | договорные отношения с вузом |
| Журнал аудита | идентификатор пользователя, действие, IP-адрес, время | ст. 19 152-ФЗ (учёт действий) |

Специальные и биометрические категории данных не обрабатываются.

### Реализованные меры защиты

- Пароли хранятся только в виде bcrypt-хешей, в открытом виде нигде не логируются.
- Доступ к API — по JWT с ограниченным временем жизни, роли проверяются на каждом эндпоинте (RBAC).
- Весь трафик — по HTTPS; в контуре Yandex Cloud TLS 1.2/1.3 терминируется на Nginx,
  HTTP редиректится на HTTPS, отдаются заголовки HSTS, `X-Frame-Options`,
  `X-Content-Type-Options`, `Referrer-Policy`.
- Запросы к БД идут через SQLAlchemy ORM — параметризация защищает от SQL-инъекций.
- Журнал аудита фиксирует создание, изменение, удаление, вход, выход и экспорт данных.
- Ежедневные резервные копии БД с хранением 7 дней (`infra/yandex-cloud/backup.sh`).
- Сетевой доступ к ВМ ограничен ufw: открыты только 22, 80 и 443.

### Cookie и согласие пользователя

Приложение использует только технически необходимые cookie и `localStorage`
(JWT-сессия, выбор пользователя по cookie-настройкам). Аналитика, рекламные и
маркетинговые скрипты не подключены.

- Баннер согласия показывается при первом визите: «Принять все», «Настроить», «Отклонить все».
- Выбор сохраняется в `localStorage` под ключом `rtk_cookie_consent`
  (категории: necessary, analytics, functional, marketing + отметка времени и версия).
- Необходимые cookie всегда включены и не отключаются — без них невозможна авторизация.
- Категории analytics / functional / marketing по умолчанию выключены и остаются
  выключенными до явного согласия; изменить выбор можно в любой момент
  через ссылку «Настройки cookie» в футере.
- Политика cookie доступна на `/cookie-policy`, политика обработки персональных
  данных — на `/privacy`; обе страницы открываются без авторизации.

### Локализация базы данных (ст. 18 ч. 5 152-ФЗ)

Текущий контур (Render + Supabase `us-west-2` + Vercel) размещён за пределами РФ,
что допустимо для демо-стенда, но не для промышленной эксплуатации с реальными
персональными данными граждан РФ. Для перехода в российский контур подготовлено
развёртывание в Yandex Cloud (зона `ru-central1`): весь стек — приложение и
PostgreSQL — размещается на ВМ в РФ, данные не покидают российский контур.
План и команды — в `infra/yandex-cloud/README.md` и разделе «План миграции в
Yandex Cloud» документа «Архитектура».

Приказ ФСТЭК России № 117 от 11.04.2025 предъявляет требования к защите
информации в государственных информационных системах и к используемым средствам
защиты. Размещение в аттестованном облаке Yandex Cloud с сертифицированным
сегментом, ограничение сетевого доступа, журналирование действий и регулярное
резервное копирование — базовые меры, закрывающие организационно-технические
требования на уровне инфраструктуры.
